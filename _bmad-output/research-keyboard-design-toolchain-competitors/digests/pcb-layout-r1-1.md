# Digest: Layout / PCB / plate tooling (pcb-layout-r1-1)

Researcher scope: KLE and successors, KLE→KiCad bridges (kbplacer), plate/case builders, autorouting, and the "regenerate routing when a key moves" question. Accessed 2026-10-24. Budget used: about 15 tool calls, about 8 sources.

**Key hard question: has any tool shipped "regenerate PCB trace routing automatically when a key moves"?** PARTIALLY. kbplacer (KiCad plugin/CLI) and kle-ng's hosted PCB generator (which uses the same author's routing) can be re-run from an edited layout. They re-place the switches and diodes, re-route the switch-diode pairs (automatic or from a template), and re-route the ROW/COL matrix with a basic shortest-path, 45° router. Neither has an incremental "re-route only what changed" mode. kle-ng regenerates a fresh board every time. In kbplacer, my reading of the source is that old tracks left dangling after a re-run are deleted. None of this covers the MCU, USB, or anything other than the matrix, and the router leaves connections unrouted when it hits obstacles. I found nothing that keeps hand-routed non-matrix traces across a key move.

## Leads worth chasing

- Ergogen community footprint packs (for example ceoloide/ergogen-footprints) reportedly ship "router"/trace footprints that encode traces in config, so traces move with the points. This is unverified from my training-data hypothesis. If true, it is the closest thing to "traces regenerate on key move" for code-first ergo builders. The Ergogen researcher should check.
- kle-ng → kbplacer → Freerouting as a chain: has anyone scripted layout edit → regenerate → Freerouting CLI → done? Search the kle-ng and kbplacer issues for "freerouting".
- kbplacer issue #38 ("Column routing not working in certain conditions", 2024): a good starting point for how robust the matrix router really is.
- Freerouting PCBench corpus: check whether keyboard PCBs are included and how they score (the matrix is an easy case, MCU breakout less so).
- How much of the kle-ng PCB worker is kbplacer (the docs do not name the backend, but it is the same author, kbplacer is referenced, and the routing description is identical).
- Current status of kbplate.ai03.com and swillkb.com (a live check), and newer plate generators (for example in kle-ng, Keyboard-Tools, or "plate.keeb.io").
- KiCad 10 IPC API: Freerouting already uses it. A live "watch layout file → update footprints in the open board" plugin would be newly feasible.

## Looked for, not found

- Any tool that re-routes incrementally (only the affected key's traces) when a key moves, keeping the rest of the hand routing. None found.
- Any tool that keeps MCU, USB, or other non-matrix routing in sync with layout changes. None found. kle-ng explicitly leaves the MCU, USB, and outline to the user.
- Keyboard-specific real-world results for Freerouting or AI autorouters. None found, only generic or vendor claims.
- A kbplacer README statement on how existing tracks are handled on re-run. Not documented, and the evidence is from source only.
- Case generation or firmware (QMK/VIA keymap) export in kle-ng or kbplacer. Not mentioned in the docs I read.
- Current maintenance or uptime evidence for the swillkb and ai03 web builders.
