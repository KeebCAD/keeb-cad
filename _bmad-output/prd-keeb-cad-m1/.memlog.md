- (decision) Outline shaping = small set of geometric ops: outline keys (key-derived shape), draw primitives, boolean operations; expected to compose to arbitrarily complex shapes.
- (decision) Outline primitives and polygon vertices are anchored to layout nodes (key/group/board origin) via same anchor+offset rule; moving a node moves only what is anchored to it.
- (decision) PCB edge, plate, case shapes derive from shared named outlines; offset (expand/shrink, with corner style/fillet) is another geometric operation alongside primitives and booleans.
- (decision) Cutouts: part-owned cutouts (switch hole, screw holes, USB/MCU case-wall window) come with the part and follow it; other cutouts are user primitives subtracted via booleans.
- (decision) Unibody deferred past M1, but layout model must be ready for it (no split-only assumptions baked in).
- (decision) PCB: non-key parts (MCU, display, TRRS, battery connector, power switch, reset) are slot parts anchored to layout nodes; switch/diode/LED per key come from the key-cell template.
- (decision) Routing on layout change: keep routes that remain valid, reroute only what the change broke (incremental, not regenerate-from-scratch).
- (decision) No manual trace editing in M1; routing is automatic. If routing hits a wall, export to KiCad (escape hatch, stops syncing) is acceptable for M1.
- (decision) Production output: when routing completes, keeb-cad exports fab-ready gerbers + drill directly (M1 requirement); KiCad project export is fallback when routing cannot complete.
- (decision) Plate = derived shape (same geometric ops + part-owned cutouts); a design may have several plates (e.g. switch plate + MCU cover); each exports DXF/SVG.
- (decision) Case = tray template built from 3D operations (user can open and edit underlying ops). M1 3D op set = what the tray needs: extrude, offset, booleans, z-position. Op set must be extensible (tilt/chamfer/loft later for tenting/curved), not hard-limited to straight extrusion by design.
- (decision) Firmware: matrix, pin mapping, physical layout derived from design and follow changes; keymap (keys, layers) is authored in keeb-cad in M1.
- (decision) Firmware target M1 = ZMK only (wired + wireless). Keymap/firmware model must be firmware-agnostic so QMK can be added later without changing the design.
