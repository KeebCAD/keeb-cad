The Forge · 24 October 2026

keeb-cad

A visual keyboard design tool where every layout change shows up live in the outline, PCB, case and firmware.

The pain was never lost hand work. It was fear of committing: changes looked so expensive that the design stalled before it started.

Locked decisions

  • Live everywhere: a layout change appears at once in outline, PCB, case and firmware.
  • Honest "instant": simple changes are live. Complex routing runs in the background with visible progress, and the tool never pretends autorouting is solved.
  • Relative, structured layout model: inspired by Ergogen, not a copy of it.
  • Freedom where it's cheap: geometry is free, add-ons are curated, and you define your own key cells (switch + diode + LED placement) for every key.
  • Remix through building blocks modelled on well-known boards, plus switch-type swaps and wireless.
  • One tool, two entry points: "Remix any keyboard…" and "Ergogen's power with a visual editor…"

Rejected, and why

  • KLE / kle-ng format, and contributing to kle-ng. Absolute positioning makes one idea cost a dozen edits.
  • "Preserve hand edits" as the wedge. The one evidenced user never had hand edits to preserve.
  • Importing KiCad boards for remixing. It's lossy, because absolute coordinates carry none of the designer's intent.
  • Startup-style kill metrics, for now. The project is personal-first and built with AI. Revisit at milestone 2.

Weak points that survived

  • Demand from others is unproven: one evidenced user (Sergii). Milestone 2 tests it.
  • What does dragging one key mean in a relative model: the key, the column, or the rule?
  • Routing the MCU, USB and add-ons is the promise most likely to break. Pre-routed MCU zones are proposed, not yet accepted.
  • kle-ng ships about every 8 days in the adjacent visual space.
