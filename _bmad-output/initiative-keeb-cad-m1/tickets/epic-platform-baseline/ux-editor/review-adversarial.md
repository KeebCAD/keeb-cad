# Adversarial review — keeb-cad editor UX spines

Reviewed: `DESIGN.md`, `EXPERIENCE.md`, `.memlog.md` (decision log, lines cited as `memlog:N`), against architecture spine AD-1..AD-21 + Glossary + Conventions and PRD §4.0, FR-1..18, SM-5. Date: 2026-10-26.

## Verdict

**Revise before editor stories.** The visual spine is sound. The behaviour spine has two blocking problems: one SM-5 step goes through a mechanism the architecture does not have (pitch), and both sides of a split-reversible board (right-half keymap, per-side population, side-qualified violation ids) have no UI. Below those sit a cluster of input-overload contradictions (Esc, Tab, Delete, right-click, drag on empty canvas, Firmware capture) and a drag write-back rule that cannot tell a correction term from an authored term. All are fixable in the spine without touching the architecture, except where noted.

Counts: critical 2 · high 10 · medium 17 · low 8.

## Findings

### Critical

- **[critical]** SM-5 step 4 "change pitch" goes through the wrong mechanism (EXPERIENCE.md J2.4 "Ctrl+click `kp` … every chain re-spaces"; J1.2 "pitch from parameters `ks`/`kp`"). In the architecture, pitch is `pitch-x`/`pitch-y` in `meta` (AD-8), `u` resolves against it, and the chain step is `(size(n−1)+size(n))/2` **in `u`** (AD-4). A user parameter `kp` re-spaces only the expressions that name it. It does not change `u` or the default chain step, so "every chain re-spaces" is false. The spec also has no surface for editing `pitch-x`/`pitch-y`: the Layout row lists "pitch" but no field, panel or command. SM-5 cannot be run end to end as written. *Fix:* add a Pitch control (two expression fields, `pitch-x` / `pitch-y`, in the Layout inspector when nothing is selected, mirroring PCB design rules) and rewrite J1.2/J2.4 to use it. Drop `kp` from the examples, or define it explicitly as an ordinary parameter that is unrelated to `u`. Decide whether "change pitch" in SM-5 means x, y or both.
- **[critical]** The right side and side-qualified ids have no UI, but the keymap, population and violations depend on them (EXPERIENCE.md Open Items: GAP "whether the derived right side is drawn", GAP "per-side population"; Firmware row "keycaps with legends in the shared viewport"). AD-19 keys the keymap by **side-qualified** slot id, and the right half's bindings must be authored (Corney is split, SM-4). AD-6 puts violations and pads on `left/`/`right/` ids. Unresolved consequences: (a) Firmware cannot bind right-half keys; (b) clicking a violation that names `right/thumb-home` has nothing to select; (c) the voice example `overlap: thumb-home ↔ thumb-tucky` drops the side qualifier that Conventions requires; (d) the wireless design (FR-5, SM-3) differs by population (reset, display, battery, power switch), and there is no way to set it. *Fix:* decide before Firmware/PCB stories. Draw the derived right side in Firmware (and optionally Layout/PCB) as read-only, mirrored, selectable for bindings and population only. Map a `right/x` selection to authored `x` for geometry edits. Add a population control (per-side "fitted" toggle in the inspector, command `setFitted`). Use side-qualified ids in every violation message.

### High

- **[high]** Drag on empty canvas has three competing meanings, and 2D pan/zoom is never specified (Interaction Primitives "Box-drag on empty canvas multi-selects"; "empty space inside a frame → selects the group"; memlog:20 shared viewport; 3D "left-drag orbit"). Group frames nest, and the top-level / matrix group frame encloses almost the whole board. So "empty canvas" barely exists: a press-drag inside any frame is a group drag (it moves the whole matrix), and box-select is reachable only outside the board. Nothing says how to pan or zoom the 2D shared viewport. The floor is a 1366×768 laptop, so a trackpad is likely, and a trackpad has no middle button. *Fix:* group selection by handle click only (not empty space). Empty-space drag inside or outside a frame = box-select. Pan = Space+drag / middle-drag / two-finger scroll; zoom = Ctrl+wheel / pinch (cursor-anchored); add a "fit" key. List these in the shortcut table. 📐 The laptop-floor decision was made for screen size only; it also implies trackpad input, which none of the drag decisions considered.
- **[high]** Drag write-back cannot tell its own correction term from an authored term (Interaction Primitives "Write-back … later edits update that same trailing term"; memlog:13). Expressions are stored as plain quoted strings with no marker, and comments are not preserved (AD-8). An authored `0.25u + 2mm` or `wall - 1mm` is indistinguishable from a previous correction, so a drag silently rewrites the user's intent (`0.25u + 2.37mm`, or flips `- 1mm`). Rounding is also unspecified, so drags write float noise (`0.3700000001mm`) into a file meant for stable, diffable output. *Fix:* rule: update the trailing term only if it is a bare `mm`/`deg` literal joined by `+`/`-` **and** was written by a drag/nudge in this session (tracked in Pinia, not the file); otherwise append a new term. Round written values to a fixed precision (e.g. 0.01 mm / 0.01°), and remove a term that reaches 0. Optionally add a grid/snap toggle.
- **[high]** The chain drag rule has two homes for one delta (Interaction Primitives "changes its own step (gap/offset from the previous sibling)"; AD-4). A drag along the chain direction could go into `gap(n)` or `offset.x`; both move the key identically. This breaks the "one way to do each thing" principle and makes write-back non-deterministic. The drag delta is also in world space and must be resolved into the anchor's rotated frame (rotation carries, AD-4); the spec does not say so. *Fix:* pick one, e.g. along-direction → `gap`, perpendicular → `offset.y` (in the previous sibling's frame), rotation untouched. State that deltas are converted into the node's anchor frame.
- **[high]** Multi-selection drag, nudge and rotate are undefined when the selected nodes depend on each other or sit in different frames (Selection levels "Shift-click adds / box-drag"; Nudge; Rotate "about its pivot"). If node B is anchored to selected node A (or is A's later chain sibling), moving both moves B twice. An arrow key is a world direction, but each offset is in its own rotated anchor frame. Rotating a multi-selection about "its pivot" could mean each node's own pivot or one common pivot. *Fix:* apply moves only to selected nodes with no selected ancestor in the dependency graph. Convert world deltas per node. For multi-rotate, use each node's own pivot (or forbid it in M1).
- **[high]** Firmware capture mode swallows the app's own controls and cannot capture common keys (Binding field "Selecting a key focuses it … keypresses are captured; Tab captures and advances; Esc leaves the field"; memlog:54). (a) Esc, Tab and Delete/Backspace cannot be captured as bindings, yet Corney's keymap uses them. (b) Ctrl+Z, Ctrl+K, Ctrl+1..5 and Ctrl+S are captured as `key` bindings, so with any key selected in Firmware there is no undo, palette, workspace switch or save without first pressing Esc. (c) Browser-reserved combos (Ctrl+W/T/N, Ctrl+Tab) and OS/WM combos never reach the page. (d) "next key" for Tab has no defined order (index? physical? across sides?). (e) Capture is a focus trap, which contradicts the Accessibility Floor ("everything keyboard-reachable"). *Fix:* make capture explicit (Enter or a `Capture` button arms it for exactly one chord, then disarms). Outside capture, Tab/Esc/Ctrl+* keep their global meanings. Capture uses `KeyboardEvent.code`. Esc, Tab and Delete are bound via the picker or by typing their name. Define the advance order (e.g. matrix row-major, left then right side).
- **[high]** The SM-5 climax cannot be seen where it happens (J2.2 "outline and plate follow under the hand"; memlog:58; IA table: the Layout canvas shows keycaps, frames and anchor links only). The edit happens in Layout, but outline and plates render only in Shapes, and plates only when one is selected. A keypress (`Shift+]`) has nothing "under the hand". After rejecting the combined canvas (memlog:19–20), the climax still needs that view. *Fix:* give Layout a faint, non-interactive outline (and optional plate) underlay, toggled by a chip as in PCB, on by default, and rewrite J2.2 to match. Or run the climax through the status strip only and drop "under the hand".
- **[high]** The 3D viewer and Assembly view are scope additions, and the journeys depend on them with no fallback (3D Scope Flag; J1.11 "A shows plates and PCB at real heights"; J2.2 "Case greys"; J2.5; SM-5 step 5). The flag is raised but J1/J2 are written as if approved. Plate and PCB solids are a new derivation with no stage owner. AD-10 allows shared derivations only in `model.resolve`, and the Glossary defines **preview** as 2D only. "Fast 3D preview" is in Deferred. If architecture or PO declines, J1.11, J2.5 and the Case workspace canvas have no specified behaviour. *Fix:* write the fallback now: Case canvas = 2D plan of the case footprint plus a status-strip/inspector state for rebuild, STL download as the fit check. Ask architecture for a `preview3d` decision (owner package, Glossary term) before marking Case stories ready.
- **[high]** Ctrl+S "asks location first time, then saves to file" does not work in Firefox, a stated target (File lifecycle memlog:32; Foundation "Chromium, Firefox"). The File System Access API (`showSaveFilePicker`, persisted handles) is Chromium-only. In Firefox every save is a fresh download (`corney(1).kdl`), so the `saved` / `unsaved changes` state cannot be trusted there. *Fix:* in Firefox, Ctrl+S = download, and the top bar says `downloaded` with the time, not `saved`. Or declare Chromium the editing target and Firefox best-effort. Record this as a platform row in Responsive & Platform.
- **[high]** Firmware layer reorder, delete and duplicate break layer references (Layer tabs "drag reorders … Delete … Duplicate"; AD-19; Glossary **id** covers design, node, shape, vertex, construction point and case operation, but not layers). `layer-tap`, `momentary-layer` and `toggle-layer` bindings reference a layer. If layers are referenced by position, a drag reorder silently retargets them, and a delete leaves dangling references. *Fix:* raise with architecture: layers get stable ids (Glossary + AD-19), and bindings reference layer ids. UX: deleting a referenced layer is rejected with a message naming the referring slots, or it removes those bindings in the same command (AD-2 cascade).
- **[high]** Per-side population and Save As have no surface or journey, so the wireless design (FR-5, SM-3/SM-4 "both designs") is not reachable (Open Items GAP population, GAP Save As; Surface closure last rows). *Fix:* add J3 "Wireless from wired": Ctrl+Shift+S → swap parts / set population → reroute. This exercises AD-9 provenance and per-side population.

### Medium

- **[medium]** Esc has 6+ meanings and no precedence, and it means opposite things in different modes (Shortcuts "Esc: clear selection, close overlay, end pick mode, leave field, leave isolated cell mode"; Expression field "Esc restores" = cancel; `Pick vertices` "Esc ends" = keep the rows; AD-2 gesture cancel during a drag is not listed). *Fix:* define one stack, innermost first: cancel the active gesture/drag → cancel the field edit → end pick mode (state whether picked rows are kept) → close overlay → clear selection → leave isolated cell mode. Make pick modes end with Enter (keep) and Esc (discard, one undo step per pick session).
- **[medium]** Tab has three meanings in a field: commit, accept autocomplete, focus traversal (Expression field "Enter/Tab commits … Tab accepts"; Firmware "Tab captures and advances"; Accessibility "keyboard-reachable"). With the dropdown open, Tab both accepts and commits. Enter on the `Create parameter <name>…` row is unspecified. *Fix:* with the dropdown open, Tab/Enter accept the suggestion only. With it closed, Enter commits, and Tab commits and moves focus to the next field. Picking `Create parameter` opens its own field; the open expression gesture stays uncommitted (see next item).
- **[medium]** Expression gesture lifecycle has holes: blur, Ctrl+Z inside the field, and nested commands (Expression field "every keystroke … previews live as a gesture"). Undefined: what happens on blur (click on the canvas, Ctrl+click a parameter, workspace switch, tab takeover); whether Ctrl+Z in a focused field undoes text, cancels the gesture or undoes the previous command; how `Create parameter` (a `setParameter` command) interleaves with an open gesture, since AD-2 allows one gesture. *Fix:* blur with a valid value = commit; blur with an invalid value = restore. Ctrl+Z in a field = native text undo; the gesture is untouched until commit. Before a command dispatches during a field gesture, the gesture commits first.
- **[medium]** The "single-key shortcuts only when no field is focused" rule does not cover modifier and navigation keys that a text field also uses: Delete, arrows, Shift+arrow, Ctrl+arrow (word jump vs 0.05 mm nudge), Ctrl+D, Home (Shortcuts table). *Fix:* when any text field or the binding field has focus, every canvas command (nudge, rotate, delete, duplicate, Home) is off. Only Ctrl+K, Ctrl+S, Ctrl+Z/Shift+Z (with the semantics above) and Ctrl+1..5 stay global.
- **[medium]** Delete is ambiguous between a focused layer tab and the canvas selection (Layer tabs "Delete on a focused tab deletes"; Shortcuts "Delete: delete"). In Firmware a key selection exists while a tab can have focus. *Fix:* Delete acts on whatever has keyboard focus. A canvas selection is the target only when the canvas has focus; show which on the cheat sheet.
- **[medium]** 3D "right/middle-drag pan" contradicts the user's explicit correction "right-click is ALWAYS a context menu, never a direct action" (memlog:52 vs memlog:55; EXPERIENCE.md 3D viewer vs Context menu row). *Fix:* 3D pan = middle-drag or Shift+left-drag. Right-click opens the context menu (right-press without movement), or ask the user whether a drag threshold is acceptable.
- **[medium]** Re-anchor keeps the old expression and adjusts the trailing term, which preserves meaningless intent (Re-anchor `[ASSUMPTION]`; memlog:17). An offset of `0.25u` from the previous key, re-anchored to a construction point, becomes `0.25u + 37.12mm`, and later pitch changes move the node for no reason. Rotation and pivot also change under a new anchor frame. Not covered: a way to reset to the **default anchor**, and how the picker handles targets that would create a cycle (AD-3 rejects them). *Fix:* re-anchor flattens offset x/y/rotation to literals (an expression survives only when the anchor frame is a pure translation of the old one). Disable targets that would create a cycle, with a hover reason. Add `Reset to default anchor`.
- **[medium]** Nudge-burst = one undo step has no boundary, and the climax depends on it (Nudge `[ASSUMPTION]`; J2.2 `Shift+]` "PCB shows `waiting for drag to finish`"). A burst is not an AD-2 gesture unless modelled as one, and background stages start only on commit or idle (AD-11). The status vocabulary says "drag" when the input is a keypress. *Fix:* model a burst as a gesture that commits after N ms (e.g. 600 ms) with no nudge/rotate key, or on any other input. Rename the status to `waiting for edit to finish`.
- **[medium]** Violations, counts and export-blocked reasons have no staleness treatment (Violations panel; Export menu `Blocked: 2 DRC errors, 15 unrouted`; Status strip "error count"; AD-11 "never shown as current"). `unrouted` and `drc` come from background or route-dependent stages. During routing they reflect an older revision, and F8 can jump to ids that no longer exist. Mid-routing, dozens of transient `unrouted` entries flood the panel and F8. *Fix:* tag violation groups with their source revision. Show stale groups hatched with `stale`, and make F8 skip them. Collapse `unrouted` into one row with a count while routing runs.
- **[medium]** STL/STEP "blocked only while the case is rebuilding" lets a stale case through (Export menu row; State Patterns `waiting for drag`; AD-11). During `waiting for edit`, or after a failed rebuild, the last good solid is from an older revision. *Fix:* STL/STEP are enabled only when the case output is `current`. Otherwise show `Blocked: case stale (rev …)` or `Blocked: case failed: <message>`.
- **[medium]** `stale · rev N` and `copied from <design> · rev N` contradict the Glossary (DESIGN.md Stale; State Patterns; memlog:32). A **revision** is a content hash, not a counter. *Fix:* show a short hash (`rev 3f2a`), or define a session-local revision counter in Pinia and name it something other than "revision".
- **[medium]** There is no surface for typed command rejections (Toast row lists only undo and migration; Conventions "commands that can't apply return a typed rejection"; AD-2 "deleting a vertex is rejected while a shape uses it"; AD-3 cycle rejection). Delete or anchor actions can fail silently. *Fix:* rejection toast in `{colors.warning}` ▲ with what + where (`rejected: vertex v-07 is used by outline-base`), plus a Toast row in Component Patterns.
- **[medium]** Pick modes and the anchor picker are mouse-only, which contradicts the Accessibility Floor's "everything keyboard-reachable" (Anchor picker "click a target node on canvas"; Pick vertices, Pick LED order). *Fix:* in pick mode, Ctrl+K (or typing) jumps to a target by id, then the 3×3 grid is navigable with arrows + Enter.
- **[medium]** Which gestures exist in each workspace is undefined (Canvas row describes Layout only). Can a key or footprint be dragged in PCB, Shapes or Firmware? If yes, the drag writes the slot's offset, which the user may read as editing an output (AD-1). Can primitives other than vertices (rectangle, circle) be dragged in Shapes? *Fix:* add a per-workspace gesture matrix: Layout = node drag; Shapes = vertex/primitive drag; PCB, Firmware = select only (no geometry drag in M1).
- **[medium]** `Alt` during drag collides with the platform: Firefox on Linux/Windows toggles the menu bar on Alt keyup, and several Linux window managers move the window on Alt+drag (Shortcuts "Alt (during drag)"). *Fix:* preventDefault on Alt keyup while a gesture is active, or use Shift for compensate. Test on the user's WM.
- **[medium]** Single-letter and bracket shortcuts (G S P T V M L I A ? [ ]) break on non-US layouts if bound by `event.key` (e.g. Ukrainian: `[`→`х`, `]`→`ї`, G→`п`). *Fix:* bind by `KeyboardEvent.code`, and show labels from `navigator.keyboard.getLayoutMap()` where available.
- **[medium]** Ctrl+1..5 collides with tab switching in Chromium (Ctrl+1..8, Linux/Windows) and Firefox (Ctrl+1..8 on Windows, Alt+1..8 on Linux). Pages can usually preventDefault them, but focus outside the page (address bar) or a future PWA/kiosk change behaviour, and the user's muscle memory switches browser tabs. Ctrl+Shift+S is Firefox's screenshot shortcut. *Fix:* verify both in a 10-minute spike in Chromium and Firefox on the user's machine. Keep Ctrl+1..5 only if preventDefault holds, and add an alternative (e.g. `1..5` as single keys when no field is focused, or Alt+1..5 in Chromium). Use the palette `Save as…` as the fallback for Ctrl+Shift+S.

### Low

- **[low]** Ctrl+D (bookmark), Ctrl+K (search bar), Ctrl+O (open file), Ctrl+S (save page), `?`/`/` (Firefox quick find) and F8 (DevTools resume, only with DevTools focused) are all browser defaults the app must preventDefault. These are preventable in both browsers when the page has focus. *Fix:* one global keydown handler that calls preventDefault for the listed chords, plus a Playwright test per chord in both browsers.
- **[low]** Home (Case top view) is also the caret key in fields. That is safe under the focused-field rule (above), but Home is not on many laptop keyboards without Fn. *Fix:* add an alias (e.g. `0` or Shift+H) and a palette command.
- **[low]** Words outside the Glossary in UI copy: "tracks" for routes (J2.2 "dashed ratsnest turning into tracks"; Glossary: **route**), "mcu" for **module**, "fan", "Amber" (State Patterns violation; the palette has Yellow), status entry "Plate" when there are several plates, "Outline" as an output (the outline is a shape resolved live and never goes stale on its own). *Fix:* "routes", "module pins", "Plates" (worst state across plates), "Yellow". Define what `Outline` status means, or fold it into `Plates`.
- **[low]** The undo toast `Undid: rotate thumb` implies a full restore, but AD-12 says undo may change copper (routes are not on the stack). *Fix:* after undo, PCB shows `routing N/M` as usual. Note in J2 Failure that copper may differ but stay electrically equal.
- **[low]** Undo toast command names ("move thumb-home") do not match the model commands a chain drag actually issues (`setGap`/`setOffset`). *Fix:* the toast uses one display label per command, from a table in the model command registry.
- **[low]** The mechanics of `Take over editing` are unstated: what the demoted tab does with an open gesture, autosave and routing (AD-13 "only that tab saves … never write the routing section"). *Fix:* the demoted tab cancels its gesture, stops autosave, shows the read-only banner, and drops in-flight background results.
- **[low]** `T` opens "tree + parameters", but the rail has two icons, and J2.4 reaches parameters only via Ctrl+click. *Fix:* T = tree, a second key (e.g. `K`/`=`) = parameters, plus a palette entry.
- **[low]** Construction point = intersection of two lines: parallel or coincident lines have no result and no violation kind (AD-16, Conventions violation owners). *Fix:* ask architecture to add a `model` kind (e.g. `construction-undefined`). The UI shows ● on the construction point.

## Angles not covered by the decisions

- 📐 Five bundles were accepted unchanged (memlog:35). Most findings here sit inside those bundles (shortcuts, expression editing, output state). The shortcut table was never tested against a real browser or the user's non-US layout and WM.
- 📐 The decisions optimise for Layout. Firmware and Case got shortcut-level detail but not the same contradiction pass, and the side and population questions were parked as GAPs even though two success metrics (SM-3, SM-4) run through them.
- ☝️ "Spines win on conflict with any mock" is fine, but several journey steps (J1.2 `kp`, J2.2 "under the hand") were written from the mocks' fiction, not from the architecture. Re-check every J step against an AD before stories are cut.
