Canvas model storyboard

Styling is deliberately neutral and identical to the direction mocks (greyscale + one muted accent #4d6a85, system font). This page compares structure only, not look.

Sergii rebuilds the Corney Island left half (outer, pinky, ring, middle, index and inner columns, 3 rows, thumb fan thumb-tucky, thumb-home and thumb-reachy). Each row follows the same five steps, rendered in one of three canvas models. The arrows name the action that switches stage. PCB routing is shown mid-run (41/56 routed, 15 unrouted) and the case mid-rebuild (stale, 62%).

  • Decisions already logged hold in all three rows: drag in a chain (Alt compensates), typed values and expressions with trailing mm/deg correction terms, arrow nudge and [ ] rotate, anchoring through the inspector picker, glossary terms only, live and background stages with staleness always marked, one gesture = one undo step.
  • No 3D view in M1: every row shows the case stage in 2D (a wall-offset outline with screw bosses, a section, or both) plus its parameters or operations.
  • Frames are 384 × 240 sketches of a laptop-size browser window. Only the parts that differ between models are drawn in detail.

What this feels like

  • You never leave the keyboard drawing. Switching stage changes the emphasis, so the thumb fan stays in the same place on screen through all five steps.
  • Every stage uses the same 2D vocabulary (outline, footprints, wall band, legends). Case and keymap are slightly forced into plan view: the case section is only a line plus parameters, and the keymap is legends on the real geometry.
  • Outputs live in a persistent status strip at the bottom. Background progress (PCB 41/56, Case stale 62%) is always in view, whichever mode you are in.

Gains

  • Best fit for SM-5 'every output visibly updating': dimmed layers of the other outputs move with the edit, inside the same frame, at no extra cost.
  • One selection, one camera and one undo context, so cross-cutting work (nudge a key to clear a PCB keep-out) is a mode key, not a context switch.

Costs

  • A case section and a keymap layer grid don't fit naturally in a plan-view canvas. Case editing is limited to parameters plus a section line, and keymap layers can only be flipped on the geometry, not seen side by side.
  • Laptop fit is good (one canvas plus tool strip plus a narrow inspector). But six modes on one canvas need strict rules for dimming. Otherwise the PCB mode with keys dimmed looks crowded at 1366 px.

What this feels like

  • Each step is a fresh screen with only its own tools, like moving between KiCad's schematic and PCB editors or Fusion 360's workspaces.
  • The case room can show what the case really is: an ordered list of operations and a true cross-section with wall, floor, PCB and plate. Keymap becomes a clean matrix grid you can scan layer by layer.
  • You learn about other outputs from tab badges (▲ 1, 41/56, 62%), not by seeing them. To see the PCB react to a thumb move you have to go to the PCB tab.

Gains

  • Each stage gets the view that suits it (section for case, grid for keymap, layer manager for PCB). Nothing is forced into plan view.
  • Uncluttered on a laptop: one tool set at a time and no dimming rules. The tab order mirrors the linear first build.

Costs

  • SM-5 is only shown indirectly: badges change, but you can't watch geometry follow the edit unless you switch tabs or add a split view. That split view is a second layout to design.
  • Ribbon plus tabs cost about 45 px of height on every screen, which hurts at 768 px. Cross-stage tweaks mean switching tabs back and forth.

What this feels like

  • The three plan-view stages, which are all footprints on the same 2D board, feel like one continuous canvas. The two stages that aren't plan views get their own rooms.
  • Two levels of switching: number keys for modes inside Canvas, and Ctrl+number or tabs for Case and Keymap. You have to learn which stage lives where.
  • The output status strip stays at the bottom of every frame, so case progress (stale 62%) is visible from Canvas and from Keymap.

Gains

  • SM-5 for geometry outputs (outline, plates, PCB) is shown in place, as in a. Case and keymap get real views (section, layer grid) without forcing them into plan view.
  • Closest to the data: layout, shapes, plates and PCB share 2D coordinates, while case (3D, background) and keymap (logical matrix) do not.

Costs

  • The case reaction to a layout edit (part of SM-5's edit script: 'change case param') is only seen as a badge or strip status unless you switch tabs. Adding a plan inset of the case to the canvas would fix it but adds clutter.
  • Two navigation models in one app (modes plus tabs) mean more to explain and more shortcut keys. Laptop fit is good on Canvas and moderate on Case, where operations, section and inset have to share the space.
