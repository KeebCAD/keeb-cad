9. Incremental routing with existing copper is a first-class design target. The default pipeline is named "PreloadedTraceGraph", and the types include `_preloadedFixedNetIds`, `PreloadedTracePortAssignment`, and `isFixedPreplacedViaRoute`. The project keeps benchmark datasets for exactly this case. `dataset-srj28-partially-prerouted` removes 50% of solved traces, and "The remaining traces are pre-routed obstacles for benchmarking routers that must finish the board **without disturbing valid existing routes**". `dataset-srj23-partially-routed-subcircuits` covers the same case. **Caveat:** the output type has `__replaces_pcb_trace_id` ("Preloaded trace intentionally replaced by this routed output"). There are also `ChangedPreloadedTraceSection`, `changedPreloadedTraceSectionCount`, and an option `USE_PARTIAL_RIP_ROUTING_WITH_PRELOADED_TRACES`. So the router **can modify or replace preloaded traces**, and I found no documented way to lock them. The keeb-cad app would have to verify that fixed traces come back unchanged, or post-filter the output. | d.ts lines 257-258, 980-1012, 5033-5034, 5194-5241, 6282; dataset-srj28 README; dataset-srj23 README | tscircuit | 2026 | accessed 2026-10-26 | high (preloaded input supported) / medium (that it may alter them) | capability

11. Runtime: the package is ESM-only (`"type": "module"`). The main bundle `dist/index.js` is a 3.3 MB minified single file whose only runtime imports are `@tscircuit/solver-utils` and `object-hash`. I found **no `node:` imports, no `Bun.` calls and no `new Worker(` in the main bundle**. There is no browser runtime entry, so in a browser you would wrap the main bundle in your own Web Worker. The README API is synchronous (`step()` loop / `solve()`), which suits a Worker. ## Per-candidate gate and criterion notes

### @tscircuit/capacity-autorouter (default pipeline 9, PreloadedTraceGraph)
- G1 no network: **PASS, probably.** The network cache is in opt-in Networked/HdCache pipelines, and the default pipeline should avoid it (F12). The spike must confirm this with network blocked.
- G2 licence: **PASS.** MIT per the LICENSE file and GitHub SPDX. package.json lacks a `license` field (F3).
- G3 Web Worker: **PASS, probably.** The main bundle is pure ESM with no Node/Bun APIs and a sync step API (F11). Not executed in a Worker yet.
- G4 fixed copper: **PASS with caveat.** Preloaded traces and partially-prerouted datasets are core (F9). But the router may replace or "rip" preloaded traces, and I found no lock flag. Verify, or diff the output against the input (F9).
- Keep-outs / pre-routed module zone (3): **partial.** Rect and circle obstacles with no connectedTo work as keep-outs. The rotated-keepout bug is fixed. There are no polygon keep-outs (F7).
- Net classes / board edge (3): **partial.** Per-connection width yes. Per-net clearance not found. Board-edge clearance yes (`minBoardEdgeClearance`), plus `outline` polygon support (F6, F8).
- Quality on 2-layer keyboard boards (3): **unknown / risk.** Open "solved but DRC-violating" bugs exist, including through-hole vias ignoring bottom copper. The project keeps a dataset of DRC failures. No keyboard benchmark exists (F14-F16).
- Speed in browser (2): **unknown.** No numbers retrieved (F16).
- Integration (2): **mixed.** SRJ in and out is simple JSON and ESM ships with types. But the .d.ts references about 20 undeclared packages, a pnpm-strict risk; the bundle is 3.3 MB; the API churns daily on 0.0.x (F2, F11, F13).
- Ecosystem health (2): **strong activity, single npm maintainer, 71 open issues, heavy bot commits** (F4).
- Determinism (1): **likely deterministic geometry per version, unverified** (F17).

### @tscircuit/krt-wasm
- G1: unknown. It is WASM, but the loader may be Node-targeted (`pkg-node`) (F18).
- G2: MIT per GitHub. The upstream KiCadRoutingTools licence was not checked, so treat as **UNKNOWN** until checked (F18).
- G3: unknown (F18).
- G4: unknown. The README lists only rect obstacles and connected exemptions, with no mention of preloaded traces. Input traces could perhaps be converted to obstacles (F18).
- Others: global `clearance` param, per-connection width, sequential grid router. Activity has been quiet since August (F18).
