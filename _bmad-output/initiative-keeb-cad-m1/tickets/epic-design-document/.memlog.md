topic: A design file that saves, reopens and undoes
updated: 2026-10-26T19:52
---


- (requirement) R1 (parent R18; architecture AD-8): a design is one canonical KDL v2 file with format-version and the 14 sections in AD-8 order, each with its schema skeleton in model; the canonical writer fixes order and quoting, ids are minted by model, and load-then-save of an unchanged design is byte-identical.
- (requirement) R2 (parent R18; architecture AD-8): older format versions migrate forward on load; a newer version opens read-only with format-too-new; a failed migration reports migration-failed and never overwrites; an unparseable or invalid file reports where and replaces nothing.
- (requirement) R3 (parent R18; architecture AD-2): every authored change is a named command in one registry with a display label; a command that cannot apply returns a typed rejection; removal cascades to everything keyed to it; every command undoes and redoes; the log is not persisted.
- (requirement) R4 (parent R18; architecture AD-2, AD-11; EXPERIENCE.md Gesture model, Expression field): a gesture is begin, update, commit or cancel; each update yields a revision the live stages consume; a commit is one undo step, a cancel restores; a command dispatched mid-gesture commits the gesture first.
- (requirement) R5 (architecture AD-17): the parameters section holds named values with units; one parser evaluates the AD-17 grammar in model.resolve only, reporting unit-mismatch and unresolvable-reference; renameParameter rewrites every use; deleting a referenced parameter is rejected naming its users; a parameter change re-evaluates every dependent expression.
- (requirement) R6 (parent R17; architecture AD-11): the pipeline runs live stages per revision and background stages in Web Workers from committed revisions or after a debounce; background stages report progress, partial and failed results and are cancelled by a newer committed revision; every output is tagged with its revision (and routing hash) and one whose tag differs is reported stale, never current, including on cache hits; each output exposes its state (current, waiting for edit to finish, rebuilding N%, stale, failed).
- (requirement) R7 (initiative Decision 2026-10-25; architecture AD-15): an export registry lets each stage register its exports, each reporting available or blocked with a reason; the same file and app version give the same export bytes.
- (requirement) R8 (parent R18; architecture AD-13; prd FR-18): all persistence goes through the storage interface (save, load, listVersions), writing the whole design atomically with the routing section valid for that revision; browser autosave is the source of truth; Chromium saves the file in place after the first save asks for a location; Firefox saves by downloading <design>.rev<hash>.<ext>; no network call is needed.
- (requirement) R9 (architecture AD-13; EXPERIENCE.md State Patterns File): one tab edits a design; others open it read-only and never write; taking over editing makes the other tab cancel its gesture, stop autosave and drop in-flight background results.
- (requirement) R10 (parent R5; architecture AD-9): Copy design makes a new design with a new name and id that records its source design and revision, leaving the original untouched; Save to file keeps the same design and id.
- (constraint) Initiative C1 (browser-only, current desktop Chromium and Firefox), C2 (stable outputs) and C3 (architecture binds) bind this epic.
- (decision) 2026-10-26 refined from parent R5, R17, R18, architecture AD-2, AD-8, AD-9, AD-11, AD-13, AD-15, AD-17 and EXPERIENCE.md (gesture model, file states); chrome and expression field split to epic-editor-shell.
