## 5. Uncovered by the spine (questions, not answers)

- **U1 (23.3 generic checks)** ☝️ The ticket's "so later stories' commands are covered automatically" survives, but nothing proves the checks in 23.3: zero registered commands. Options: (A) build the harness in 23.3 over a test command registered only in app's test container, with a toggled bug as proof; (B) move the generic checks to 13.2, the first story with real commands; (C) keep both: harness in 23.3, a 13.2 verify row that it covers AddGroup. Recommendation: A — the harness and NewDesign's replaceDesign path (also in layer 3: "after a replaceDesign … deeply frozen") land together, and B would leave replaceDesign's freeze check unproven at the app level until 13.2.
- **U2 (accept event doubles autosaves)** 📐 AD-13 says `pipeline` "posts both derived files at every seq, even unchanged", and autosave now saves on every accept event. So each command produces a commit-event autosave and an accept-event autosave of an unchanged bundle: two rolling versions per edit, halving the 20-version history, and twice the IndexedDB writes. The spine doesn't say whether `acceptDerivedFiles` with files equal to the held ones (same revision tags and content) replaces the `Committed`/emits, or whether autosave skips an unchanged bundle. Needed before 23.5 is planned.
- **U3 (23.7 launch on other load failures)** AD-8 and 23.7 name only `design-invalid` → new design. An autosave that is `file-unreadable` (a truncated write) or `format-too-new` (a newer app wrote it in another tab) isn't covered: new design, start screen, or banner? The `LoadError` design hands this to `app` ("chooses what to show") without a rule.
- **U4 (derived-file readers and writers)** `replaceDesign` parses each derived file with its own schema, and 23.5 round-trips "each file of the bundle". Which story owns `schema`'s RoutingFile/FingerprintsFile schemas and `design-file`'s readers and canonical writers for them: 23.3 (it parses them) or 23.5 (it stores them)? 23.3's ticket says "design-file's canonical writer" (singular).
- **U5 (format version in LoadError and MigratedBundle)** EXPERIENCE.md's banner shows "format N" and 16.1 reports "the source version for the Upgraded from format N toast", but `format-too-new` has no version field and `MigratedBundle` none either. Per AGENTS.md a new field waits for the spine's Data Schema: ask before 16.1 (it doesn't block 23.3).
- **U6 (new-story / 23.3 boundary)** Q5 defines `Action.apply(input): AsyncResult` and Q4 says "23.3 codes the action path". Does the di-class story ship the `Action` interface with `apply` (unused until 23.3) or only `ActionHandle` statics plus availability, with 23.3 adding `apply`? Also whether the store's eager duplicate-id check over statics and the lazy instance resolution belong to the refactor (likely yes: they replace the current definition objects).
- **U7 (spine-internal leftovers)** ☝️ Not ticket items, but the spine still contradicts itself after the amendment:
  - AD-11 "The design mirror" (line 424): "Undo and redo also send the routing file they restore, and `newDesign` the empty files it sets, each with its patches." — contradicts Q3/Q8 (NewDesign goes through replaceDesign's whole-bundle event, no patches).
  - AD-2 "Design state" (line 200): "The routing and fingerprints files are not part of it (AD-1)." — "it" now reads as the `Committed` value, which holds them (Q2); should say "not part of `Design`".
  - AD-10 `design` package line (line 330): "Its commit event hands each commit's patches, seq and revision to whoever subscribes" — misses the accept event and the whole-Committed variant.
  - AD-8 (line 296): "each missing one filled empty" — omits unreadable/failing (Q13); minor.

## 6. Owners

- **(a) "Commands and actions become di classes" (Q6):** a new entry in epic-a-new-design-opens, **23.15** (`next_id = 15`), after 13 (and 14 if the rename should land first; not required), with 23.3's `after` gaining 15. Scope from Q5: `Command<Input>`/`Action<Input, E>` instance interfaces and `CommandHandle`/`ActionHandle` class-side interfaces in `design` replacing `defineCommand`/`defineAction`; the `commands`/`actions` multi tokens list classes; the store's duplicate-id check reads statics at startup and resolves an instance lazily at first run; `store.run(Handle, input)`; 23.2's test command (rename) ported to a class; the static-id literal type test (R29). No user-facing change. Owner of the ticket text: Sofia.
- **(b) Accept event + autosave on acceptance (Q9):** **23.5**. Q9 says "the first story where pipeline posts derived files to main"; per current tickets that is 23.4 (pipeline echoes derived files every seq) with 23.5 coding `acceptDerivedFiles` and autosave ("none until 5 fills it through acceptDerivedFiles"). 23.5 is the only story holding both halves. Blocked on U2. Alternative if Sergii reads Q9 as "first real derived files": 7.1/7.2, which would mean removing the echo from 23.4 and acceptDerivedFiles from 23.5.
- **(c) "Saved routes couldn't be read and were reset" notice (Q15 → epic-keep-my-work):** **16.1** (Old files migrate, newer and broken ones are refused safely), which already turns load outcomes into shell notices ("Upgraded from format N" toast, format-too-new, corrupt file). Proposed addition: "a load whose replaceDesign returns a non-empty emptied tells the user which saved file was reset (e.g. 'Saved routes couldn't be read and were reset'), through the shell's toast". The toast mechanism itself is still a spine Open Question ("the first slice with a toast"). A separate 16.x story is the alternative if 16.1 grows too large.
