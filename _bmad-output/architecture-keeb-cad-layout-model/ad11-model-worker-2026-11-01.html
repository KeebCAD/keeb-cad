  W->>W: apply patches, check hash

  C-->>E: CaseOutput bodies when ready
  • During the drag nothing runs: only the dragged nodes move on the canvas (AD-2).
  • A newer revision lets the current stage finish, then starts from the visible stage again.

Rules that change in the spine

ADTodayBecomes
AD-11Live stages are computeds on main, read directly by the editorLive stages run in one model worker. After each applied command: the visible stage first, within 100 ms; hidden stages after, their violation counts marked updating until they arrive. The editor draws from posted snapshots. A newer revision takes over at stage boundaries. One-off requests from a small fixed list, tagged with their revision. pipeline lives in the model worker and feeds case and routing over MessageChannels.
AD-11 crossingOne crossing in reactive, plain valuesSame principle; the crossing is the hand-rolled protocol: one TS union of about 7 message kinds (design, patches, focus, stage, issues, request/response, failed), plain values and transferred buffers only.
AD-10One reactive graph (read as on main)The one graph lives in the model worker; main uses Vue reactivity only for the design ref and editor state.
AD-11 outputsBackground results replaced whole in a shallowRefEvery stage output is packed by an own struct-of-arrays codec, ids pre-sorted by the worker, defined beside its output type in model; the editor reads typed views straight from the transferred buffers, with no plain objects and no index on main; a round-trip test per codec. Spike: 0.02–0.075 ms on main per PCB message, lookup 0.02 ms, 1.3 KB.
AD-2Immer patches offPatches on: they are the payload to the worker, tagged with revision and hash.
